# First exercise

Use a test business, a test recipient and a paused campaign only.

1. Create `BUSINESS-TRUTH.md` with one offer, customer, geography, customer value and verified outcome.
2. Run both read-only preflights.
3. Complete `META-TRUTH.md` without secrets.
4. Write one end-to-end funnel in `META-GROWTH-PLAN.md`.
5. Create a dry-run campaign receipt.
6. Create a dry-run WhatsApp template-test receipt.
7. Review the account, budget, recipient ending, message purpose and rollback.
8. Only then decide whether to authorize the paused Meta build and owned-number test.

The exercise passes when the objects remain paused, the test recipient is owned or explicitly authorized, webhook signatures validate, delivery is distinguished from acceptance, and the funnel report names its unknowns.


## Next lesson: your saved enquiry becomes a sales workflow

No ads account is required for this lesson. Use the student's existing CRM or fictional local
fixtures. Read BUSINESS-TRUTH.md once and inspect the source before adding anything.

1. Map the first CRM's enquiry, operator and email receipt to the seven-stage guide.
2. Write one enquiry acknowledgement, one genuine utility update and one marketing follow-up.
   Identify the permission, purpose and service-window/template eligibility for each.
3. Build the Supabase webhook locally; prove challenge, signature and durable event handling.
4. Implement WhatsApp/email status, a human call task and the READY/NOT READY decision.
5. Prove one ready lead books without nurture; one not-ready permitted lead queues marketing.
6. Withdraw that permission before dispatch: prove the queued message is suppressed.
7. Test duplicate callbacks, competing workers and two requests for the final booking slot.
8. Only after these checks, prepare a specific hosted-test and owned-recipient review.

The [guide's acceptance scenarios](skills/connect-meta-whatsapp/references/student-sales-automation.md#acceptance-scenarios)
are the implementation gate. Report local synthetic proof separately from signed live delivery
and live-customer activation. A handwritten plan or successful API response alone does not pass.
